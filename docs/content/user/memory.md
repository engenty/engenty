# Agent memory

Engenty's agents remember things worth remembering: a preference you stated,
a decision made on a project, something about a contact that changes how to
handle them, or a rule for the whole company. This isn't your chat history —
it's a small, growing set of notes the agents write down and check before
acting, so you don't have to repeat yourself.

You can see and edit everything an agent has remembered at
**Settings → Memory**.

## What gets remembered

Agents write memories sparingly — the rule they follow is *"would a colleague
write this down in their notebook?"* Typical examples:

- You correct an agent or state a preference ("keep replies short", "always
  CC billing on big invoices") — remembered against **you**.
- A decision is made on a project that should shape future work on it —
  remembered against **that project**.
- An agent learns something about a contact that changes how to deal with
  them (their preferred contact method, their timezone) — remembered against
  **that contact**.
- A rule that should apply company-wide — proposed for the **organization**,
  and held for your approval (see below).

Agents are told, explicitly, to skip anything derivable from your data,
anything only relevant to the current conversation, and anything sensitive.

## The four places memory lives

Settings → Memory has a tab for each:

| Tab | What's in it | Who can edit it |
| --- | --- | --- |
| **Profile** | The assistant's quick read on you — your role, language, current focus. Reset-only; the assistant maintains it itself. | Nobody edits it directly — you can reset it. |
| **My memory** | Preferences and facts agents have learned about you specifically. | You. |
| **Projects** | Decisions and lessons tied to a specific project. | Anyone with write access to that project. |
| **Organization** | Company-wide rules and guidelines. Anything an agent proposes here waits for a human to approve it before it applies to anyone. | Approvers edit and decide; everyone else can read. |
| **Entities** | Notes about a specific contact or other object. Also shown as an "Agent notes" card right on that contact's page. | Anyone with write access to that record. |

Each tab reads and edits like a normal document — headed sections
(Preferences, Facts, Lessons, Decisions, Guidelines), plain text you can type
into. There's no record table to wrestle with: type a correction into a note
and save; type a new line under a heading and it becomes a new memory; delete
a block and it's gone from what agents recall.

## Correcting or removing a memory

If an agent remembers something wrong or outdated, you have two ways to fix
it:

- **Just tell the agent.** Say "that's not right anymore" or "forget that" in
  chat — agents are instructed to update or remove a memory the moment you
  push back on it, and to say so.
- **Edit it directly** on the relevant tab in Settings → Memory: rewrite the
  text, or delete the block entirely.

Agents will never remove a memory someone on your team wrote by hand, or an
approved company-wide guideline — those changes are left to a person, on
purpose.

## Organization memories need approval

An agent can *propose* a company-wide rule, but it can never make one active
on its own. Proposed entries show up highlighted on the **Organization** tab
for anyone with approval rights, with **Approve** / **Reject** right there —
approving is what makes the rule apply to every agent going forward.

## Keeping it tidy

You don't need to do anything for this — once a week, an agent reviews each
scope and quietly merges near-duplicate notes, retires lessons that newer
decisions have superseded, and clears out low-confidence notes nobody's
touched in a couple of months. It never touches anything a human wrote or
anything still waiting on approval.

## Transparency

When a memory shapes an agent's answer, it will usually say so — "going by
your preference for short emails…" — so you always know when something
you're seeing is influenced by what the agent remembers, and can correct it
on the spot if it's wrong.
